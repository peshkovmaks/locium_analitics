# Locium Analytics — Техническое задание и план развития

## 1. Описание проекта
**Locium Analytics** — личный кабинет аналитики для селлеров на маркетплейсах (Ozon, Wildberries, Яндекс Маркет). Сервис забирает заказы, остатки, рекламу и финансы из API площадок, считает unit-экономику, валовую и чистую прибыль, ДРР, и показывает всё в едином дашборде.

---

## 2. Текущий стек

### Backend
- **Python 3.12**, **FastAPI**, **SQLAlchemy 2.0** (async), **PostgreSQL 16**
- **Celery** + **Redis** для фоновых задач (синхронизация)
- **JWT Bearer** аутентификация (`/api/v1/auth/login`)
- **CORS**: `allow_origins=["*"]`
- **Docker Compose** (api, db, redis, celery_worker, celery_beat)

### Frontend
- **React 19** + **Vite 8** + **Tailwind CSS 3.4**
- **React Router DOM 7** (BrowserRouter)
- Сборка в `backend/app/static/` (`base: '/static/'` в vite.config.js)
- API-клиент в `frontend/src/lib/api.js` с авто-редиректом на `/login` при 401

### База данных
- Таблицы: `users`, `shops`, `products`, `sales`, `stocks`, `adverts`, `shop_products`, `product_shop_mappings`
- Поле `products.canonical_sku` — «родной» артикул для объединения одного товара с разных площадок
- Таблица `product_shop_mappings` связывает `shop + external_sku → product`

## 4. Известные ограничения и «техдолг»

- **Миграции**: нет Alembic. При изменении моделей нужно вручную править БД (`ALTER TABLE`) или пересоздавать volume.
- **Синхронизация WB/ЯМ**: не подключена (только Ozon).
- **Склеивание товаров**: механизм `canonical_sku` заложен, но UI для ручного объединения товаров ещё не сделан.
- **Импорт себестоимости**: только ручное редактирование по одному товару.
- **Алерты**: сейчас только на остатки &lt; 10 шт. Нет алертов на маржу/ДРР.
- **Роли**: в схеме есть `UserRole.admin / viewer`, но на фронте не разделены права.

## 6. Контекст для AI-ассистента

При работе над кодом помнить:
- Backend запускается через Docker Compose (`api`, `db`, `redis`, `celery_worker`, `celery_beat`)
- БД: `postgresql+asyncpg://mp_user:mp_password@db:5432/marketplace_analytics`
- Все SQLAlchemy-модели должны иметь корректные `back_populates` и `relationship`
- Frontend билдится в `backend/app/static/`, `base: '/static/'`
- Auth: JWT Bearer, токен хранится в `localStorage` как `token`
- `canonical_sku` — ключевое поле для объединения товаров с разных МП
